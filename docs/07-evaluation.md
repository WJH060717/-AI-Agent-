## 1. 验证什么

分别验证遥测接入、检测、关系重建、入口候选、Agent证据质量、软件可靠性和展示能力。不能把网络流分类准确率当作攻击溯源准确率，也不能拿漂亮演示替代独立评估。

所有目标是待实测门槛；如果未达成，记录偏差、条件和限制。小样本只支持受控实验结论，不做生产性能与统计显著性承诺。

## 2. 实验室与三条演示线

推荐隔离实验环境：一台回放/编排行为的测试机、两台Linux目标（应用机A、内部服务B）、一台日志收集机；资源不足时同一物理机运行容器/虚拟机。实验网络与校园/生产网隔离，默认禁止出站，必要依赖先下载。

| 场景 | 活动与需要的遥测 | 真值 | 展示预期 |
|---|---|---|---|
| S1 多阶段可疑活动 | 受控认证失败后成功→已知会话关联进程→A到B管理连接且B成功认证→向实验接收端传测试文件；含网络/主机/告警 | 每步起止、实体、会话、允许因果边、数据是否可见 | 重建至少4阶段的可观测路径；缺会话时明确断点 |
| S2 周期通信 | 测试客户端按固定间隔连接实验接收端，混入普通浏览/解析活动 | 连接时刻、真实正常/测试背景 | 提示周期行为，报告可能正常心跳，不能凭周期断言木马 |
| S3 正常与缺证反例 | 正常维护登录、监控心跳、备份；另做S1缺主机日志版本 | 运维批准记录、可见来源、被移除证据范围 | 正常替代解释；缺证时降低结论，不补造攻击跳跃 |

实验只需可控行为与已知日志，不要求编写漏洞利用、真实恶意代码或访问第三方目标。无害行为复现不等同于验证真实利用成功检测；必须在材料中明确测试覆盖的阶段。

## 3. 数据集组织

目标33个独立运行：开发12、验证6、测试12、演示3。开发各S1/S2/S3四个；验证各两个；测试各四个；演示每类一个。这里S3内部平衡正常运维与缺证版本。独立运行需要不同seed/时间段/背景活动/资产映射；不能把同一次运行的日志拆成多个集合。

同一原始采集的派生版本（删源、时钟扰动、格式转换）必须保持同一split。测试集额外扰动使用测试运行的派生版本，单独报告稳健性结果，不作为新增独立样本。演示数据不参与指标统计。

33次运行以参数化夹具/安全场景回放为主，S1至少完成一组实际采集的多源链路。每份数据标 `real_capture/synthetic/replayed/derived`；若没有真实采集，必须缩小成果声明为合成数据概念验证。

公开 CIC-IDS2017 有PCAP和带标签流，可作为网络检测补充；不能默认它提供本项目所需的主机进程真值与完整攻击因果图。网络分类标签仅用于相应任务，不补造主机链。三周不强制下载大型公开数据，优先授权实验室数据。依据：[UNB 数据集说明](https://www.unb.ca/cic/datasets/ids-2017.html)。

## 4. 真值清单

每个run保存：

```text
run_id / scenario_id / seed / split / provenance_type
authorized_scope / operator / capture_start / capture_end
asset_inventory_version / clock_manifest / sensor_configs
raw_object_hashes / parser_version / dataset_version
ground_truth_steps: step_id, start/end, actor_asset, target_asset,
                   observable_event_ids, activity_label, visibility
ground_truth_edges: from_step, to_step, relation, evidence_available
ground_truth_origins: observable_entry, earliest_visible_point,
                      true_test_origin, left_censored
benign_contexts / expected_unknowns / reviewer_1 / reviewer_2
```

真值保存于评估目录，不能写进运行库payload、文件名提示或Agent上下文。采集编排记录是主要真值依据，检测器输出不能反过来作为标签。B标注，D或A复核；争议保留并给出两种口径。

## 5. 数据泄漏防止

按完整运行/活动链分组切分；预处理拟合、历史p95、阈值选择只看dev/val；D8后冻结，test只评一次正式版本。IP、日期、文件名、特定攻击工具字符串不能作为标签捷径。改变地址后复跑检测与图，检查是否依赖演示硬编码。

需要修bug时可以用test定位，但修复后的该集合不再作为完全未见验证；记录迭代，新增保留样本或明确称回归集，不继续宣称盲测。

## 6. 指标定义

| 指标 | 计算口径 | 初始目标/呈现 |
|---|---|---|
| 记录核算率 | accepted+duplicate+quarantined / input，audit另报聚合 | 100%，任何无法核算均为缺陷 |
| 有效记录解析率 | 正确规范化记录 / 已知合法输入记录 | ≥99%；人为畸形夹具单独统计 |
| 重复导入稳定性 | 二次导入后新增唯一事件数 | 0（同对象/同sensor条件） |
| 检测precision/recall/F1 | 以rule×run已标注活动为单位，一对一匹配；重复告警另计误报负担 | 各场景与宏平均；目标F1≥0.80，不报保证值 |
| 正常运行误报 | 正常run的告警数量/运行时长及被误判事件率 | 数量、分钟数、原因全部给出 |
| 图边precision/recall/F1 | 事件级可观测因果/关系真值边，一对一实体与关系匹配 | 可观测边F1目标≥0.80；未知边不强算负例 |
| 完整步骤覆盖 | 成功关联的真实可观测步骤 / 所有可观测步骤 | 与证据缺失率同时报告 |
| 可观测入口Top-1/Top-3 | 入口候选命中已知可观测入口的run比例 | Top-3目标≥0.80；单列被窗口截断run |
| 引用存在/授权率 | 合法且同快照引用 / 所有引用 | 发布必须100% |
| 事实谓词校验通过率 | 被接受的observed谓词与字段一致比例 | 发布必须100%；拒绝数不能隐去 |
| 自然语言不支持率 | 人工判为无支持/矛盾的事实性断言 / 所有事实性断言 | 目标≤5%，零断言时记N/A而非100%准确 |
| 缺证诚实率 | 关键证据缺失时正确输出未知/断点的案例比例 | 报n/N；门禁要求所有固定安全反例通过 |
| 调查耗时 | 接受调查到终态，含排队/失败/重试 | 每次值、p50/p95、超时率；目标p95≤90s |
| 查询延迟 | 规定查询集、100次请求，客户端计时 | 10万事件下p95≤2s，记录并发 |
| 新数据摄取吞吐 | 空dataset，原始日志分片每10秒500条，持续30分钟，共90000条；核对持久化和隔离 | 无静默丢失；结束后60s内队列排空为初始目标 |
| Agent成本 | 每次输入/输出token、次数、估计费用 | 按实用模型价格和日期计算，不编总成本 |

检测匹配：预测与真值需同rule/行为类、相同强资产、时间窗交叠；用最大一对一匹配，未匹配预测算FP，未匹配真值算FN。无法观测的攻击步骤不纳入“可观测召回”分母，但必须另报总步骤与不可见步骤，避免隐藏覆盖不足。

路径评估将模型返回边投影到真值step后去重，不能把一条真值边匹配多条预测抬高召回。入口候选区分真实编排起点与观测起点；NAT或代理无证据时正确输出未知优于猜中隐藏真值。

12个测试run很小，比例报告分子/分母和Wilson区间（适用二项比例）；F1等按run分组bootstrap给出探索性区间或明确样本不足。不能对高度相关日志行做独立样本显著性检验。

新数据摄取压测与演示回放分开：前者经真实上传/解析/持久化链路进入空dataset，分片保持稳定来源定位，不混入同源重复；后者对既有事件创建analysis_session并控制可见进度，只统计分析/界面速度。两者都可按50EPS输入，但不能把session成员插入速率或重复导入缓存命中当作规范事件新增吞吐。audit样例另外报原始record与聚合事件的速率。

## 7. 对比与消融

| 组 | 能力 | 目的 |
|---|---|---|
| B0 | 单规则告警 + 模板 | 最小基线 |
| B1 | B0 + 图关联/路径 + 模板 | 测图关联对路径的作用 |
| B2 | B1 + 单次LLM摘要，无补证 | 区分“能写报告”和“会调查” |
| B3 | 完整Agent + 引用校验 | 检查补证和约束价值 |

相同输入、规则、知识、模型版本和预算；B2/B3使用相同模型。Agent实验在测试12run上各重复3次，报告所有运行均值、离散程度、失败率。资源不够时先每组1次完整测试，再对预先指定的6run做3次重复，不能只重复结果差的组。

对比目标不是确保B3“全面更好”：B1可能更快且事实性更强，B3应体现缺口检索和解释质量，成本更高须如实报告。人工评审去掉组别、随机顺序，由两人按事实正确、引用支持、路径解释、未知项四项0/1/2评分，并报告分歧。

# D11 已实现的离线入口与口径

`eval.validate_manifest --config`、`eval.run --config --output`和`eval.metrics --input --output`已实现，精确可执行命令见[d11-runbook](d11-runbook.md)。下文旧版“示例命令”仍是设计草案，未实现的参数不能直接运行。本次仅工程协议桩实验；不生成正式F1或人工评分。

配置以eval/contracts.py的EvaluationConfig为准：version、profile、model_mode、repeats、B0–B3完整groups、budget、runs；每run有run_id/scenario_id/provenance_type、可选context及source_type/sensor_id/object。object含相对路径与sha256；只能绑定已冻结授权data输入，标签路径禁止作为运行输入。formal可传inventory_freeze(path/sha256)绑定新清单冻结，默认旧D9冻结仍会拒绝未采集/未复核资料。测试数据消费登记先于预测，即使失败也不能悄悄重跑成盲测。

运行结束后才读取已复核真值：ground_truth_steps的每项含id、observable、event_ids或locations；locations按原始对象sha256及record_start/end匹配实际source_locators，禁止依据告警反推标签。ground_truth_edges用from_step/to_step/relation/observable；activities用id/rule_id/强asset_id/start/end/observable；observable_origins为step ID列表，left_censored单列。标签必须适配实际脱敏资产映射；IP不替代asset_id。不可见活动从召回分母剔除；未知边不强制记负例。

检测采用最大一对一匹配（同规则、强资产、时间相交），重复预测不能抬高召回；图按事件→step投影去重，未知/不可见单列。Top-k保留原始排序中的未知项，不把第4位正确候选提升到Top-3。宏F1先按run汇总重复，至少12个有分数run才给按run重采样的固定seed bootstrap95%，否则标样本不足；比例给n/N与Wilson95，相关重复的合并比例不伪造独立置信区间。零分母、缺标签为null。失败/blocked/partial保留在预测文件和失败率内。

B0实际规则结果、B1确定性图模板、B2单次摘要无工具/无修复、B3受控Agent均走现有核心代码；离线评估专用B2策略不更改线上Agent。B2/B3共用同模型与预算上限；protocol_stub不是live验收。输出manifest绑定源码/模型运行模式与配置，predictions.jsonl记录各组实际状态/模式/引用/预算/before-after，metrics可离线复算并验证摘要。无双人自然语言评分时不报告“结论正确率”；引用校验通过不等于自然语言正确。

`scripts.benchmark_p1_replay` 先在新库准备合成源事件，经真实本地 HTTP 创建 replay session，记录实际时间、可见成员进度和 100 次查询耗时，并逐字节派生摘要核对原 events 不变。默认 100000 事件、1000 EPS；可另测 2000 事件、50 EPS。输入准备不计为新增日志吞吐测试，超过 10000 的检测保持 partial。原始记录/失败和实际执行版本见 artifacts/p1-replay-*；历史 D11 的 30 分钟吞吐结果不当作本轮新测量。
