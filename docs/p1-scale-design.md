# P1 大规模检测与回放界面增量

本轮只推进 D10-004 的本地工程验收，保留其余五项外部验收条件。基线为 dev16，原始文件摘要和字节归档见 artifacts/p1-scale-baseline.json / zip。迁移 0001–0006、规则冻结配置、原始日志及历史发布包不可改写。

## 检测

默认完整检测范围从 10000 提升为 100000 个会话成员；仍读取完整固定会话，不能仅检测前 N 条。R03/R04 按原有匹配字段建立索引，保留同一键的全部证据。R05 使用连续窗口前缀矩计算，按最早起点搜索，禁止删除内部异常点；阈值附近用原 Welford 算法复核，保留冻结配置和 finding ID 语义。

增加类型化资源限制：输入 JSON 字节、工作单元、秒数、finding 数与引用总数。限额耗尽统一返回 RULE_RESOURCE_LIMIT，检测和目录发布在 savepoint 中回滚；原始事件与已完成的导入成员仍保留，批次/回放标记 partial。未预期异常继续传播。每次完整检测覆盖 R01–R06，完整不代表完整攻击因果链；调查快照上限仍为 250。

## 回放 UI

在已有导入界面创建 1–1000 EPS 的回放，显示固定源水位、成员进度、作业状态及检测状态，可取消、按作业 ID 重新打开、返回导入会话。Connection 新增可选 sessionId；不修改 default_session_id。事件与调查都使用显式选定会话；令牌/数据集/会话变更中止旧请求并清空旧结果。令牌仅在内存。POST 响应不确定时保留同一幂等键和参数供重试。复用已有 POST/GET/cancel 路由，不增加无必要的数据结构或列表 API。

IncidentPage.warnings 兼容扩展为字符串列表，覆盖 RULE_RESOURCE_LIMIT、REPLAY_DETECTION_PENDING、取消/失败等现有状态；前端明确展示未完成检测，不能显示无告警的完整结论。无数据库结构变更。

## 验收

全量 >10000 含六规则阳性、阴性与末尾证据；密集周期、非单调 CV、内部噪声及不确定时间与旧算法对照；资源耗尽无半发布。实际 100000 条 HTTP 导入及回放、成员集合/原始摘要核对，记录耗时和查询 P95。真实浏览器验证创建/进度/切换/恢复/取消/错误/旧响应隔离；全量 Python、PostgreSQL、类型生成、前端构建与 lint。合成工程样本不计为 33 次正式实验或真实 LLM 验收。
