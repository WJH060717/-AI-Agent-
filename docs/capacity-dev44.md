# dev44 容量表

机器：Windows 11 26200，CPython 3.12.4，模型 `disabled`。数据为 `tests.contract.test_p1_scale.mixed_events` 合成工程夹具，不是正式标签或端到端攻击实验。原始结果 `docs/capacity-dev44.json`，测量入口 `python -m scripts.measure_capacity --output ...`。

## 检测阶段实测

| 输入事件 | 检测耗时 | 峰值内存 | 检测工作计数 | 规则 |
|---:|---:|---:|---:|---|
| 1,000 | 0.103s | 0.24 MB | 17,216 | R01–R06 |
| 10,000 | 0.734s | 2.08 MB | 170,216 | R01–R06 |
| 100,000 | 9.817s | 23.46 MB | 1,700,216 | R01–R06 |

测试为单进程、无并发、无模型、无 PostgreSQL。峰值来自 `tracemalloc`，不是进程 RSS 或整机内存。

## 当前上限

| 阶段 | 上限 | 说明 |
|---|---:|---|
| 导入 | 100 MB / 请求 | `MAX_UPLOAD_MB=100` |
| 检测 | 100,000 事件 / 会话 | 超限 `RULE_SCOPE_TOO_LARGE`；超过 10,000 的完整检测仍需单独验证 |
| 检测 findings | 2,000 | 超限按资源错误处理 |
| 回放 | 100,000 事件、500/批 | 回放成员速率不等于新摄取吞吐 |
| 调查快照 | 250 事件 | 默认和最大相同；种子超限返回明确 422 |
| 快照扫描 | 20,000 事件 | 同会话/窗口候选；超限要求缩小范围 |
| 图 | 500 节点 / 1,000 边 / 6 跳 / beam 20 / top 3 | 裁剪传播到路径/报告，`truncated=true` |
| 工具单次 | 16 KB 正文 / 100 项 / 3 秒 | 分页与 coverage 保留 |
| 模型上下文 | 12,000 输入 / 3,000 输出 token | 4 次模型、6 次工具、90 秒总墙钟；默认不调用 |

## 结论边界

- “10 万条检测通过”只说明当前规则在合成事件上的检测阶段容量，不等于 10 万条端到端溯源、快照构建或模型调查。
- 调查快照 250 是独立限制；检测成功但无法创建调查时，API 返回 `SNAPSHOT_SEEDS_EXCEED_LIMIT`、`SNAPSHOT_SCAN_LIMIT_EXCEEDED` 或带 `coverage=partial` 的明确状态，不静默截断种子。
- 提高上限前必须先补测机器内存、查询延迟、图构建和并发；本表不是 SLA 或生产容量承诺。
