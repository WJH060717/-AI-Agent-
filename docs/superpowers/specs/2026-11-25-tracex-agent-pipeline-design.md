# 六阶段攻击分析流程与 Agent 调查改造规约

版本 1.0，日期 2026-11-25。性质为设计交付，功能状态为待实现，新增能力按 P2 管理。本文规定后续改造的行为及验收，实际能力以各版本验证记录为准。新增字段为设计提案，须按第八节落实契约后进入代码。

## 一、目标、基线与设计选择

贯通“采集 → 归一化 → 规则检测与标注 → 图构建与溯源 → 情报归因 → 前端展示”，让分析员看到行为为何被检测、来源追到哪里、Agent 查了什么、哪些证据改变了判断。

源码 dev41 已生成 behavior_assessments，固定行为验收为 2/16。现有数据源、规则、证据图、六种只读工具、预算、引用校验和 before/after 比较是改造基础。dev20 一次真实调查返回 17 个不同旧种子，非种子新增为 0，存在未续页问题。未来成绩须绑定新版本。源码与本机部署分别以验收和部署记录为依据。

用户指定了六步流程及保留 Agent 特色。助手选择在现有 Python、Pydantic、PostgreSQL、React/TypeScript 和四服务架构中增量扩展，采用单个受控调查 Agent，在初始图生成后进入补证循环，按需读取本地情报，最终组织经校验的报告。

| 方案 | 特点与代价 | 决定 |
|---|---|---|
| 各阶段独立模型决策 | 需分别验证模型解析、标注、关联和恢复，预算与审计面扩大 | 留作研究 |
| 初始图之后由一个受控 Agent 调查 | 复用状态机，模型选择查询，程序管理证据与状态 | 采用 |
| 模型只参与最终文字生成 | 能复用报告能力，对主动补证覆盖有限 | 用于降级说明 |

首期沿用本地导入和固定日志回放。实时传感器部署、组织归因引擎和新数据库均不构成本轮设计的实施前提。技术栈扩展需实际瓶颈依据。

基线见[行为验收](../../ciciot-behavior-verification.md)、真实补证记录（本地归档 `../../p1-retrieval-live-verification.md`）、[数据契约](../../02-data-contracts.md)、[Agent 契约](../../04-agent.md)。本文从属于 [PROJECT_SPEC](../../../PROJECT_SPEC.md)，第 13.9 节逐类行为验收继续适用。

## 二、主流程及 Agent 嵌入位置

~~~mermaid

    A["采集与原件封存"] --> B["归一化、身份与时间质量"]
    B --> C["规则检测与 ATT&CK 候选标注"]
    C --> D["冻结快照、初始图、路径和断点"]
    D --> E["Agent 选择调查目标与查询"]
    E --> F["白名单工具读取同一快照"]

    G -->|缺口可查且预算允许| E

    H -->|需核查且预算允许| E
    H --> I["Agent 整理报告草稿"]
    I --> J["有限谓词、引用和权限校验"]
    J --> K["前端展示、证据回查、导出"]
    E --> L["外部采集缺口建议"]
    L -. 人工取得材料并新建调查 .-> A
~~~

Agent 的主要位置在第四步与第五步之间。图提供路径和缺口，Agent 决定查询顺序、提出替代解释、选择何时结束。第六步展示简短行动理由和实际结果。

第一至第三步由确定性程序执行。Agent 可建议需要哪种新增记录，采集由授权人员执行。工具只读固定快照。后到材料先导入并完成发布，再由用户新建调查；各次调查保留自身快照和报告，跨次差异按新增输入解释。

## 三、六阶段责任与交付

### 3.1 采集

目标是取得足以验证目标行为的观测及其来源。

| 输入层 | 优先复用的材料 | 可回答的问题 |
|---|---|---|
| 网络 | PCAP、Zeek conn、Suricata EVE | 洪泛、探测、协议冲突、专项告警 |
| 认证与主机 | Linux auth/audit；后续按需接入 Sysmon | 认证事务、会话、进程创建和执行 |
| 应用与终端 | 授权的应用、防护、文件或终端事件 | 注入尝试、上传策略、后门及浏览器异常 |
| 绑定上下文 | 采集前固定的资产、地址有效区间、时钟和观测域 | 端点身份、跨源时间可比性 |

MUST 保存来源、授权范围、对象 SHA-256、原始定位、采集时间范围、传感器实例、解析版本和失败记录。新增来源先登记输入枚举与类型契约，至少有可回读正例、正常对照、损坏或缺字段反例。

MUST 按来源统计物理记录、聚合事件、重复、隔离及未完成记录。audit 多片段沿用既有聚合守恒关系。采集失败、解析失败需显示具体范围。

首批按第 13.9 节缺口推进，优先认证场景，其次选择证据齐备的 DNS/ARP 或 Web/终端场景。原件缺信息时登记未知及补采字段。新样本重新冻结，原固定输入及失败结果保留版本。

### 3.2 归一化

目标是生成可比较、可追溯且保留不确定性的 NormalizedEvent。

MUST 复用 event_id、source_locators、time_quality、sensor、asset_id 和现有类型化对象。跨源关系依据强实体、有效期映射和明确事务键。缺可靠出生标记的 PID 保持弱身份。网络包与连接沿用各自语义。

MUST 保存各传感器独立观测。只有可靠原生身份和规范语义一致时才按现有规则去重。同 IP、同 PID、时间接近或同文件名仅用于候选检索。多源计数注明主来源，旁证独立保存。

MUST 区分非法输入隔离、合法但字段不足的质量标记、字段完备的检测输入。空值保持未知，Agent 只接收白名单脱敏投影。新适配器先定义事件类型、事务身份、脱敏和定位，再实现解析；任意扩展字段不得直接进入模型。

### 3.3 规则检测与标注

目标是产生可复现 Finding、贡献证据和 ATT&CK 技术候选。

MUST 使用冻结规则与配置，保留命中条件、贡献事件、时间与适用范围、正常解释及缺失字段。专项设备告警需回到原件，并有设备规则版本及可信来源。

MUST 对行为检测、执行成功、影响结果、家族归属分别举证。R05 保持周期行为含义；Mirai 相关洪泛按第 13.9 节发布有证据的协议行为。知识标签仅提供技术候选。

MUST 在本次适用规则全部完成后发布完整检测。条数超限、资源耗尽沿用 RULE_SCOPE_TOO_LARGE、RULE_RESOURCE_LIMIT 和检测 savepoint 回滚约束，其他错误遵循既有失败语义。模型调用不是产出规则结果的前提。Agent 可复核证据、提出调查目标，阈值调整经过独立开发、冻结与回归。

### 3.4 图构建与溯源

目标是形成可回查路径，明确入口候选、影响范围和断点。

MUST 复用实体图与事件级投影。每条边携带 evidence_refs、kind、method_version、时间区间及匹配依据。严格路径要求可靠时间先后，误差区间重叠保留 order_uncertain 关联。observed、inferred 和缺证断点可区分。

MUST 保留同 session、parent 下全部合法证据。进程到连接须有直接绑定或契约允许的受限匹配依据；仅同主机、同窗时保留 process_socket_binding 缺口。最早观测点保留覆盖及 left_censored 说明。

沿用 beam width 20、最多 6 跳、top 3 路径、500 节点/1000 边上限。全部输入范围在裁剪前校验，truncated 传播到路径、报告和前端。

Agent 的 before 仅由种子组成。每次工具完成后，在已知集合上重新计算可支持的判断及路径投影。完整快照图仅供确定性分析及授权前端查看；模型的初始图摘要和后续建议严格使用 K 投影。前端分别标明完整快照图与 Agent 已核查范围。

会话根停止与路径压缩为后续优化，先测量噪声和召回代价。按进程名硬排除可能掩盖被入侵服务，需保留停止理由、被省略范围及反例。

### 3.5 情报归因

目标是解释已观测行为与知识的关系，并给出有范围的来源判断。

| 结果 | 依据 | 发布口径 |
|---|---|---|
| 行为与技术解释 | finding、固定 ATT&CK 条目 | 技术候选、依据、正常解释 |
| 可观测来源与路径 | 当前快照实体和关系证据 | 已证实资产/进程/路径范围及未成功原因 |
| IOC 情报上下文 | 后续导入的可信本地情报 | 来源、版本、时效、匹配类型与冲突 |
| 家族或组织假说 | 独立归因证据、可核验知识 | 缺材料保持未知，技术相似度作为候选解释 |

首期使用 knowledge/attack-18.1 和 get_technique_context。knowledge_refs 必须来自同 run 已完成调用，最多 5 条，目录摘要绑定缓存与恢复。Agent 可据知识提出当前快照内能够核查的替代解释。

本地 IOC 富化为可选后续增量，接入前定义来源契约和有界只读工具，注明许可、获取时间、有效时间、置信度含义、匹配及失效规则。运行时外网查询、原始日志上传超出本设计授权。

事件引用与知识引用分别核验。技术重合分数不得发布为真实操作者身份。未知、冲突及未加载原因进入报告。

### 3.6 前端展示

沿用“导入数据 → 查看异常 → 阅读报告”。六阶段作为进度和结果来源说明，按实际 job、run、tool action 映射；未执行、失败、部分完成显式展示，导入后由用户发起调查。

报告依次呈现以下内容。

1. 行为检测及该项溯源结果，复用 behavior_assessments。
2. 关系图、时间线、候选路径、观测范围和断点。
3. Agent 补证前后，新增非种子记录、支持或削弱判断的证据。
4. 情报解释、待核事项和正常替代解释。
5. 运行模式、调用、停止原因、预算预留、usage 估算和账单可用性。

结论和边可点击回查同一快照证据。正文、HTML、JSON 使用同一份已校验报告。工具详情沿用 analyst/admin 权限，viewer 可读脱敏结果及证据。

只展示简短可审计的行动理由。completed、passed、返回记录数或动画完成不得表达为溯源成功。切换身份、数据集、会话沿用旧响应隔离。

## 四、Agent 调查协议

### 4.1 已知集合和目标

S 为固定种子，R 为同 run 已完成工具返回的快照事件，K = S ∪ R。建议、计数及模型事实摘要只依据 K、已知缺口与工具覆盖。摘要裁剪须显式提示，完整 K 仍保留在审计中。

目标说明待验证关系/行为、已有支持、替代解释、所需字段、可用工具和结束条件。复用 open/supported/weakened 判断与 open/resolved 缺口。自由假说按既有 unknown 输出；新增可发布判断种类必须配套有限校验器。

### 4.2 工具选择与反馈

| 需求 | 首选工具 | 必查依据 |
|---|---|---|
| 核实父子与会话相关过程 | get_process_context | 强进程 ID、生命周期、深度、引用 |
| 寻找认证或特定类型事件 | search_events | 资产/事务、时间窗和合法过滤 |
| 查行为前后及正常解释 | get_asset_timeline | 资产归属、时间和来源覆盖 |
| 核查原件与字段冲突 | get_event_evidence | 已知 ID、哈希、安全字段 |
| 复核路径及断点 | get_candidate_paths | 当前范围、版本和边引用 |
| 技术及正常解释 | get_technique_context | 本地版本、知识用途 |

建议按“未解决目标的相关性 → 相关未读后续页或不同证据类型 → 避开完整重复查询 → 成本”排序。相关性只由已知字段估计，不预测未见事件。参数只用已知强实体和合法过滤。模型可选择其他合法查询，记录简短理由。

有 next_cursor 且未读范围仍与缺口相关时，优先建议原参数续页。改查询需记录目的及遗留未读范围。续页保持原参数、scope 和签名游标。完整重复结果按既有缓存复用。

每次查询核算返回 event_ids 与 K 的差集，更新 R，再由程序重算判断。旧种子、重复分页、知识条目及已有图边均不增加非种子数。空结果保留其范围，不能推出没有发生。

get_candidate_paths 的目标行为限定为基于 K 重算路径，复用既有入参，K 由服务端注入。它返回的路径事件必须全部属于 K，原始证据引用逐边保留，其 evidence_ids 对 R 的增量必须为零。未知端点先由事件搜索、进程上下文或资产时间线查询取得事件摘要，随后才能进入路径。该行为与当前基于全快照的路径工具存在差异，列为 M2 的必做改造并升级工具版本及缓存身份；完整图 API 继续按授权范围显示完整快照。

验收须构造一个种子尚未连接、全快照已有隐藏中间事件的场景。首次路径工具不得泄露该事件 ID、字段或关系；事件检索返回它后，下一次路径计算才可利用它。重复取得路径不能增加已知证据计数。查询预算不足时保留未复查路径的说明。
### 4.3 新行为与抓包查询

当前 SearchArgs.types 尚无 network.packet，提示主要覆盖认证和进程。M2 必须定义并实现抓包安全摘要查询，优先扩展 search_events 的类型白名单和已有时间/资产筛选。无资产绑定时只允许当前快照内合法端点过滤。禁止通过 extensions 绕过字段限制。

新行为缺口对应第 13.9 节具体证据，如 DNS 请求/冲突答复、ARP 映射有效性、专项告警事务上下文。工具返回有界白名单协议摘要；原件访问走授权证据接口，模型只见脱敏投影。每种新判断的支持/削弱条件先冻结，再启用提示。

### 4.4 状态、预算和恢复

沿用 planning → querying → checking → planning/drafting → validating。单轮最多一个模型提出的工具调用，最多 2 轮规划。硬上限为 6 次工具、4 次模型含成稿/修复、累计输入 12000、输出 3000，单模型 20 秒、累计模型等待 60 秒、总墙钟 90 秒。工具单次 3 秒、正文 16KB、列表最多 100 项。

当前快照上限 250 事件，检测会话上限 100000，分别检查。两轮单工具规划使正常查询路径最多两次规划工具调用，6 次是预算上限。知识查询也消耗机会，优先处理对结论最有影响的目标；多工具决策须另做契约变更。

连续两次无新增、轮数到限、可行动缺口解决或模型请求成稿时保存 query_stop_reason。未读页的停止保留覆盖限制。取消、预算、超时、租约失效和引用拒绝按既有状态与降级语义处理。

状态和行动写入经 Queue.guard 与 lease/version 检查。调用前持久预留，失败/中断保留预留。恢复核对模型、提示、工具、规则、图、判断及知识版本，before 和变化序号保持幂等。外部调用结果未确认时不得作为完成结果复用。

## 五、两种补证与完整示例

快照内补证查询已导入的固定成员。外部补采由用户取得新授权材料、导入并创建新调查。旧 run 不跨快照，新报告说明新增输入范围。

以下为验收设计，ID 和数值由实际运行产生。

认证事件组种子显示重复失败后成功，并有强会话或进程线索。初始报告列出会话到进程待核关系及发起侧缺口。Agent 首轮用 get_process_context 核查已知强进程，次轮按实际结果查询资产时间线或认证记录。非种子返回进入 after，程序更新判断和路径。报告呈现可核实的目标侧过程及未证实的发起侧来源。

若快照缺进程到连接绑定，报告列出需要的主机字段和时间范围。后续具有绑定记录的新调查可显示对应路径；移除绑定记录的独立对照须恢复断点。

工程夹具验证状态机、真实领域工具和校验。真实模型验证使用预先固定材料及相同判据，需独立次数与费用授权。已见样本标为开发复验。

## 六、阶段交付和代码落点

每阶段形成可从导入到报告验证的纵向功能。端到端验收按 M1 → M2 → M3 → M4 组织，M5 按材料与需求单独排期。M1 的真实多源材料未齐时，M2 可使用既有固定 S1/D7 开发夹具推进协议、查询及判断测试，M3 可准备绑定关系的工程正反例，M4 可准备历史兼容与展示。对应真实材料到位后才完成该场景的跨阶段验收，工程夹具成绩保留其来源标记。

| 阶段 | 模块与内容 | 完成条件 |
|---|---|---|
| M1 来源覆盖及一个多源场景 | packages/ingest、contracts、导入服务、离线验收 | 正例/正常/损坏输入能对账，finding/报告/重导/回放可复验，缺料保留阻塞 |
| M2 缺口驱动 Agent | retrieval.py、context_wire.py、model.py、assessment.py、evidence_state.py、executor.py、runtime.py | 实际查询更新 before/after，重复及续页反例通过，抓包查询契约正反通过 |
| M3 有证据的路径增量 | packages/graph/service.py、paths.py、主机绑定适配及契约 | 一条目标关系正例与移除关键证据反例通过，跨域/弱身份/时序歧义拒绝强连 |
| M4 报告前端联动 | behavior_reporting.py、reporting.py、validation.py、报告/API 契约、apps/web | 检测/溯源/增益/情报/覆盖在网页及导出一致，历史字段缺省可读 |
| M5 可选本地 IOC | knowledge、版本化目录契约、新只读工具 | 来源/时效/冲突/权限/缓存漂移通过，知识和现场引用可回查 |

## 七、验收矩阵和指标

TC-PIPE 仅是本设计追踪标识，实施时登记到需求用例映射，既有 TC-001～040 继续适用。

| 用例 | 正向验收 | 反例及预期 |
|---|---|---|
| TC-PIPE-01 原始证据 | 多源原件与贡献可回读、计数对账 | 损坏/缺片/冲突原生 ID 隔离并留原因 |
| TC-PIPE-02 身份时间 | 强身份及可靠先后支持关系 | PID 复用、跨 boot/域、时间重叠拒绝强连 |
| TC-PIPE-03 检测 | 固定输入得到有证据行为候选 | 正常/相邻行为/缺字段按实计分 |
| TC-PIPE-04 补证 | 固定有目标材料夹具中至少两种工具、一个非种子及一次有依据判断变化 | 两次仅返回种子时新增为 0，保持未知，停止可复算 |
| TC-PIPE-05 分页 | 相关未读页按原参数续读、去重 | 改参数或跨 run 游标拒绝，未读不能计全覆盖 |
| TC-PIPE-06 路径 | 真实新返回支持明确关系 | 移除绑定恢复断点，纯时间邻近拒绝造边 |
| TC-PIPE-07 知识 | 同 run 完成返回的引用通过 | 未调用、错误版本、现场证据混用被拒或未知 |
| TC-PIPE-08 模型边界 | 合法查询和有限断言通过 | SQL、提示注入、伪引用、错误类型及反向事实被拒 |
| TC-PIPE-09 恢复资源 | before/after、预算、序号可恢复 | 取消或过期租约晚到结果不发布，超预算降级 |
| TC-PIPE-10 展示 | 网页、JSON、HTML 结论和引用一致 | 缺省历史字段、partial、损坏证据、旧响应正确处理 |
| TC-PIPE-11 策略对照 | 同输入及预算对比原/新策略 | 全部失败、未知、无新增和零分母保留 |
| TC-PIPE-12 新材料 | 新输入独立调查可追踪来源 | 旧快照/报告/原件摘要保持，跨快照查询拒绝 |

TC-PIPE-04 条件用于固定开发验收场景。实际输入没有新证据时，正确停止并保留未知属于有效行为。知识解释本身不计事件补证增益。

至少记录阶段处理量及失败、检测适用/完成范围、新增非种子数、判断支持/削弱次数、目标断点解决数、重复返回比例、未读范围、查询时间、调查总时间、预留费用、usage 估算和真实账单。比例分子分母须可由行动复算，零分母记 null。

有标签正式实验另计检测及路径 precision/recall，按独立采集或主机分组，派生片段同划分，标签只用于离线评分。§13.9 行为/16、历史精确分类/17、DoS/DDoS v2、Agent 指标按各自清单输出。

先验证本地协议闭环，再经新增授权验证真实模型自主选择。协议桩只证明工程链路；P1 关闭仍需各自验收证据。
