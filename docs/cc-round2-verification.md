命中的三条 conn UID 是 `CEwqBV3HVym8AUOMv`、`C59ff41J75E00jDc1k`、`CAKtPs3lDtA4dhyRs9`。离线按五元组、方向和时间唯一匹配官方 `flow=From-Botnet-V48-TCP-CC77-HTTP-Not-Encrypted` 标签。它们组成 **1 个候选、3 条连接、3 条 HTTP 证据**，不是 3 个独立攻击。只有其中 1 次请求有 2xx 且响应体字节数为正，另外两次为 404。规则报告只确认规则触发，恶意命令、执行、控制关系和身份仍未知。

## 改变的行为与文件

- `packages/contracts/{models,protocols}.py`、`packages/ingest/{http_shape,http_dns,parsers}.py`：新 HTTP 使用 schema 1.3 / parser v2，增加可缺省的客户端形态。只保留 UA 外形类别、查询解析状态与有界计数，不向证据/报告/Agent 输出原始 UA、URI、参数名值或令牌摘要。查询形态无法解析时保留未知，不丢弃其他合法 HTTP 字段。旧 1.0–1.2 继续有效，DNS 保持 1.2。
- `packages/detection/{r08,r09,freeze_cc,freeze_endpoint,registry,common}.py`、新增两份规则及各自冻结：至少 3 请求、3 个唯一关联连接、保守跨度至少 30 秒、窗口最多 600 秒，至少 1 个正字节响应；客户端和查询形态只是候选条件。连接必须唯一满足采集器/作用域/UID/完整端点/时间条件。
- R08 聚合同一 Host；R09 聚合同一远端 IP/端口的至少两个 Host。R09 只是端点关联，共享主机、CDN、不同应用可能符合；没有新增控制、服务身份或进程因果边。重复物理事件不能增加连接数，资源不足沿用检测回滚。
- `packages/agent/reporting.py`、`packages/storage/analysis.py`：既有报告链显式展示规则限制和正常替代解释，保持 `deterministic_fallback`，不是模型推理结果。
- `eval/ctu13_cc_round2.py`、`eval/ctu13_cc_audit.py`、`scripts/verify_cc_round2.py` 及对应单元/集成/浏览器测试：来源适配、仅检测后离线标签核对、全链路验证。候选应用不打包这些离线评估文件或标签。
- 生成的契约/前端类型及版本元数据同步；API 路由、依赖、数据库迁移不变。源码改动不会自动更新正在运行的 8080 镜像。

## 版本与数据依据

初始 candidate-01 的 R08 在真实样本上为 0。检查已见开发数据后发现符合形态的三条请求分属同一端点的两个 Host，因此另建 R09 和 candidate-02；没有放宽原阈值，没有改写 R08 冻结或原零命中结果，也没有写入样本 IP、域名、查询键或官方标签作为检测答案。

独立源为 CTU-13 scenario 7 / Botnet-48 的既有本地 conn、HTTP 文件；官方标签文件 SHA256 为 `df0b5338190b967bd340a0d6c1bb3c34d1bbfb4b7ffa764c2dd26f77f1a26680`。选择记录、全文件摘要、原物理行号和摘要见 `artifacts/cc-round2-01/samples-01`。正常对照为之前已唯一对齐官方 Normal 标签的 20 条连接。官方标签只用于离线选样/结果核对，不上传给运行中的检测器或 Agent。

本次读取 HTTP 源时共明确排除 77 行编码/字段类型不合法记录，其中 2 行属于所选 C&C UID、0 行属于正常对照。原始字节和逐行拒绝摘要保留，没有猜测编码或静默改写。这与第一轮适配字段范围不同，本轮增加了对原始 UA 的读取；不能沿用第一轮的排除计数。

设计参考 [CTU-13 官方数据说明](https://www.stratosphereips.org/datasets-ctu13) 与 [MITRE DET0027](https://attack.mitre.org/detectionstrategies/DET0027/)。本实现是有限日志启发式，不代表已实现完整检测策略。

## 仍未验证或未解决

1. 23 条官方 C&C 连接仍未覆盖，R08 单 Host 规则在本次真实样本上无命中；R08 正例只由合成边界测试验证。
2. 更广泛正常更新/遥测/SDK 的误报率、未见 CTU 场景和独立盲测；合成正常更新形态可触发的反例已明确保留，不能据小样本宣称零误报。
3. HTTPS/TLS 加密内容、DNS 隧道、非 HTTP C&C、真实控制命令和主机进程/socket 归属；没有对原始 PCAP 重解析来补这些证据。
4. 本次新规则的大规模吞吐/资源极限、生产部署/服务重启与新旧存量混合迁移；旧事件不自动补写新形态。
5. 真实 LLM 推理、付费模型效果和账单；本轮完全禁用模型。原有 P1/正式发布门禁未因本轮测试而关闭。
