# 06｜15 个工作日的实施计划

## 1. 排期使用方法

D1是团队实际启动日，不假定已确定开始日期。共15个工作日，建议周末只做机动与备份，不把加班当作必然产能。D1–D10每天每人6小时：任务约5小时、联调/复核约1小时；D11后转为评估、修复与交付，并保留团队级机动。前10天没有额外可用工时，出现延期立即按止损规则减范围。

任务清单预计232人时，另留98人时共同集成评估/彩排、30人时机动，总360人时。估算用于控范围，不是对未知开发难度的保证。A/B/C/D分工见总体方案；D负责知识条目整理和批量数据运行清单，B负责采集与标签质量；A协助C完成状态持久化。真值不能由生成模型自评。

每天上午冻结当日接口；下午固定一次联调；每天收工前保存可运行版本、阻塞项和第二天入口。无须等全部日志到齐才做UI，无须等模型可用才做工具与图。

## 4. 第一天逐时行动

1. 第1小时：全员读总体规划；确认硬件、权限、模型网络与竞赛材料要求；写 `docs/environment-baseline.md`。
2. 第2小时：A/C冻结事件与报告；B给出真实格式样例；D依据Schema生成页面数据，不反向发明字段。
3. 第3～4小时：A搭依赖与库；B整理最小fixture；C做一次模型JSON/工具决策连通性试验；D写四页流程。
4. 第5小时：四人一起检查从日志行到报告引用的ID如何传递；查缺字段，不追求美观。
5. 第6小时：记录版本和风险；选择D2任务；提交当前产物；不把尚未验证的模型接入写成“已完成”。

## 5. 关键路径与止损

关键路径：T-04/06/07 → T-08/10/12 → T-13/14 → T-16/18 → T-21/23/24 → T-26/27/28 → T-29/30。

- D3 未闭环：当天停止其他功能，所有人围绕一个合法样例联调。
- D5 主机采集仍不稳：保留已有授权导出数据和明确合成夹具，取消现场采集；不能把合成数据称为真实采集。
- D7 模型不可用：继续工具、图、校验与模板报告；尽快完成一次获准网络条件下的真实调用录像，并标注历史；若从未完成真实调用，必须把“Agent已实现”改为“Agent接口原型/未验收”。
- D8 图性能不足：收紧事件范围和图展示，不临时换数据库。
- D10 不完整：砍P1、PDF、复杂样式和扩展场景，保留一条完整路径+反例；未达原定验收项写入限制。
- D12 指标差：解释错误和适用范围，不能筛掉失败测试或只报最好一次。
